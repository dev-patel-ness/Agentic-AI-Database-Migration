# DDL Fixes Summary - 2026-10-01

## Problems Fixed

### 1. ✅ Escaped Newlines in View/Procedure DDL (FIXED)
**Problem:** CrackSQL translator returns DDL with JSON escape sequences (`\n`, `\t`, `\"`). PostgreSQL received literal `\n` instead of actual newlines, causing syntax errors.

**Example Error:**
```
syntax error at or near "\" LINE 1: ..."", ""first_name"", ""last_name"", ""department_id"") AS \nSELECT e...
```

**Root Cause:** `_sanitize_target_ddl()` function wasn't unescaping JSON escape sequences from the translator output.

**Fix (agents/schema_agent/__init__.py, line 71):**
```python
# Added at the start of _sanitize_target_ddl():
cleaned = ddl.encode('utf-8').decode('unicode_escape')
```

This properly converts `\n` → newlines, `\t` → tabs, `\"` → quotes, etc.

**Verification:** ✅ ACTIVE_EMPLOYEES view (Job 3cef46f7) now APPLIES successfully

### 2. ✅ FK Constraint Idempotent Handling (FIXED)
**Problem:** Foreign key constraints that already exist on the target (from previous runs, incomplete cleanup, or replay scenarios) caused APPLY_FAILED status, blocking migrations.

**Example Error:**
```
constraint "fk_departments_manager" for relation "departments" already exists
```

**Root Cause:** `apply_schema_translations()` was treating "constraint already exists" errors as hard failures instead of idempotent success (the FK already exists = goal already achieved).

**Fix (agents/schema_agent/__init__.py, lines 405-419):**
```python
if object_type == "foreign_key" and "already exists" in exc_str.lower():
    logger.info(
        "job=%s: FK %s already exists on target (idempotent), marking APPLIED",
        job_id,
        object_name,
    )
    mark_translation_applied(meta_conn, row["id"], "APPLIED")
    results.append(
        {"object_type": object_type, "object_name": object_name, "status": "APPLIED"}
    )
```

This treats duplicate constraint errors as idempotent success, allowing replay and retry scenarios to proceed without manual cleanup.

**Verification:** ✅ Unit test `test_apply_schema_translations_treats_duplicate_fk_as_idempotent` passes
